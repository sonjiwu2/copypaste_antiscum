# Формат учебного сценария

Документ описывает, как устроен файл сценария и как добавить новый.

Сценарии лежат в `backend/scenarios/*.json` и встроены в бинарник через
`//go:embed`. Приложение читает их один раз при запуске и проверяет каждый.
**Файл с ошибкой останавливает старт** — сломанный сценарий не попадёт к
пользователю.

## Быстрый старт

Чтобы добавить сценарий:

1. Создайте `backend/scenarios/<имя>.json`.
2. Заполните метаданные и узлы по описанию ниже.
3. Запустите `go test ./...` в каталоге `backend`.
4. Запустите приложение — если оно поднялось, сценарий прошёл проверку.

Ошибка при старте указывает точное место:

```text
загрузить сценарии: файл сценария "buyer_fake_delivery.json" не прошёл проверку:
сценарий "buyer-fake-delivery", узел "prepay-decision", выбор "refuse-prepay":
[transition_target_missing] следующий узел "ghost-node" не существует
```

## Метаданные сценария

```json
{
  "id": "buyer-fake-delivery",
  "version": 1,
  "slug": "buyer-fake-delivery",
  "role": "buyer",
  "title": "Ссылка на доставку",
  "description": "Покупка товара с доставкой.",
  "difficulty": "medium",
  "estimatedMinutes": 4,
  "startNodeId": "greeting",
  "isActive": true,
  "nodes": []
}
```

| Поле | Тип | Описание |
|---|---|---|
| `id` | строка | Устойчивый идентификатор. Уникален в каталоге. |
| `version` | целое ≥ 1 | Версия содержимого. См. раздел «Версионирование». |
| `slug` | строка | Человекочитаемый идентификатор для ссылок. |
| `role` | `buyer` \| `seller` | Роль пользователя. |
| `title` | строка | Заголовок в каталоге. |
| `description` | строка | Короткое описание в каталоге. |
| `difficulty` | `easy` \| `medium` \| `hard` | Сложность. |
| `estimatedMinutes` | целое | Ожидаемая длительность. |
| `startNodeId` | строка | Узел, с которого начинается прохождение. |
| `isActive` | булево | `false` убирает сценарий из каталога. |
| `nodes` | массив | Узлы сценария, см. ниже. |

Неизвестное поле в файле — ошибка. Так опечатка вроде `"slugg"` находится сразу,
а не превращается в пустое значение.

## Типы узлов

### `message` — реплика диалога

```json
{
  "id": "greeting",
  "type": "message",
  "sender": "seller",
  "text": "Здравствуйте! Товар свободен.",
  "nextNodeId": "channel-decision"
}
```

Обязателен `nextNodeId`. Вариантов выбора у сообщения быть не может.

Подряд идущие сообщения сервер выдаёт **одной пачкой** и останавливается на
первом решении или финале — фронтенду не нужен запрос на каждую реплику.

### `decision` — точка принятия решения

```json
{
  "id": "channel-decision",
  "type": "decision",
  "decisionPrompt": "Продавец просит перейти в мессенджер. Что вы сделаете?",
  "choices": []
}
```

Нужно минимум два варианта выбора. `nextNodeId` у самого узла не задаётся —
переход определяется выбранным вариантом.

### `terminal` — финал

```json
{
  "id": "unsafe-ending",
  "type": "terminal",
  "outcome": {
    "type": "unsafe",
    "title": "Деньги потеряны",
    "explanation": "Оплата ушла вне площадки."
  }
}
```

`type` итога — `safe` или `unsafe`. У финала нет ни `nextNodeId`, ни вариантов
выбора. В сценарии должны быть достижимы оба типа финала: тренажёр обязан
показывать и последствия ошибки, и результат верных решений.

## Вариант выбора

```json
{
  "id": "move-to-messenger",
  "label": "Перейти в мессенджер",
  "nextNodeId": "delivery-message",
  "safetyScore": -20,
  "criticality": "high",
  "riskTags": ["off_platform"],
  "skillEffects": [{ "skill": "channel_safety", "delta": -1 }],
  "consequence": {
    "severity": "dangerous",
    "title": "Защита площадки потеряна",
    "explanation": "Вне сервиса переписка не подтвердит договорённости.",
    "realWorldRule": "Просьба срочно уйти в мессенджер — типичный первый шаг обмана."
  }
}
```

| Поле | Видно клиенту | Описание |
|---|---|---|
| `id` | да | Идентификатор варианта. Уникален внутри узла. |
| `label` | да | Подпись кнопки. |
| `nextNodeId` | **нет** | Куда ведёт выбор. |
| `safetyScore` | **нет** | Изменение результата. `0` для безопасного, отрицательное для рискованного. |
| `criticality` | **нет** | `low` \| `medium` \| `high`. Вес ошибки для будущего прогресса. |
| `riskTags` | **нет** | Метки мошеннической схемы. |
| `skillEffects` | **нет** | Изменения навыков: `skill` и `delta`. |
| `consequence` | после выбора | Учебное объяснение. |

### Последствие

| Поле | Описание |
|---|---|
| `severity` | `safe` \| `warning` \| `dangerous` |
| `title` | Короткий заголовок результата |
| `explanation` | Почему так произошло |
| `realWorldRule` | Правило, применимое в реальной сделке |

`severity`, `title` и `explanation` обязательны: выбор без объяснения ничему
не учит, поэтому такой сценарий не проходит проверку.

## Результат прохождения

Попытка начинается со **100** очков. Значения `safetyScore` выбранных вариантов
складываются, результат удерживается в диапазоне **0–100**.

Ориентир при написании сценария:

| Характер выбора | `safetyScore` | `severity` | `criticality` |
|---|---|---|---|
| Безопасный | `0` | `safe` | `low` |
| Спорный | `-10…-20` | `warning` | `medium` |
| Опасный | `-25…-40` | `dangerous` | `high` |

Клиент не может повлиять на результат: значения берутся только из файла
сценария.

## Правила проверки графа

Сценарий отклоняется, если нарушено любое правило. Код правила попадает в
сообщение об ошибке.

**Метаданные**

| Код | Причина |
|---|---|
| `scenario_id_required` | пустой `id` |
| `scenario_version_invalid` | `version` меньше 1 |
| `scenario_role_unsupported` | роль не `buyer` и не `seller` |
| `scenario_title_required` | пустой `title` |
| `scenario_difficulty_unsupported` | сложность вне списка |

**Узлы**

| Код | Причина |
|---|---|
| `duplicate_node_id` | одинаковые `id` узлов |
| `node_id_required` | узел без `id` |
| `node_type_unsupported` | тип вне трёх допустимых |
| `message_node_without_next` | у сообщения нет `nextNodeId` |
| `message_node_with_choices` | у сообщения есть варианты выбора |
| `decision_node_too_few_choices` | у решения меньше двух вариантов |
| `terminal_node_with_next` | у финала есть `nextNodeId` |
| `terminal_node_with_choices` | у финала есть варианты выбора |
| `terminal_node_without_outcome` | у финала нет корректного итога |

**Варианты выбора**

| Код | Причина |
|---|---|
| `duplicate_choice_id` | одинаковые `id` внутри узла |
| `choice_label_required` | пустая подпись |
| `consequence_incomplete` | нет объяснения или неверная `severity` |

**Связность графа**

| Код | Причина |
|---|---|
| `start_node_missing` | `startNodeId` не найден |
| `transition_target_missing` | переход ведёт в несуществующий узел |
| `node_unreachable` | узел недостижим от стартового |
| `terminal_unreachable` | ни один финал недостижим |
| `graph_has_cycle` | в графе есть цикл |

**Циклы запрещены намеренно.** Прохождение обязано заканчиваться, а
отсутствие циклов позволяет продвигаться по сообщениям без искусственного
ограничителя шагов.

## Что не уходит клиенту

Это часть контракта, а не деталь реализации: зная переходы и веса, пользователь
видел бы правильный ответ заранее.

Никогда не публикуются:

- граф сценария целиком;
- узлы, которые ещё не раскрыты;
- `nextNodeId` любого перехода;
- `safetyScore`, `criticality`, `riskTags`, `skillEffects`;
- признак «безопасный/опасный» до совершения выбора;
- объяснение последствия до совершения выбора.

Публикуются:

- метаданные сценария в каталоге;
- уже раскрытые узлы;
- у текущего решения — только `id` и `label` вариантов;
- последствие **после** того, как выбор сделан;
- итог на финальном узле.

Проверка закреплена тестами: они разбирают сырой JSON ответов и падают, если
в нём встречается любое из скрытых полей.

## Версионирование

Попытка закрепляется за версией сценария в момент старта. Если содержимое
изменилось, а версия осталась прежней, уже идущие попытки увидят новый текст —
это ошибка редактирования.

**Правило: меняете содержимое — поднимайте `version`.**

При расхождении версий сервер не подставляет новое содержимое молча, а
возвращает ошибку: доигрывать прохождение на другой версии некорректно.

## Замена сценариев

Файлы в `backend/scenarios/` — временные данные для интеграции. Их можно
заменять целиком, не трогая код: формат стабилен, проверка при запуске
поймает ошибки.

Текущие два сценария намеренно короткие и служат для демонстрации движка.
Развёрнутый контент — зона Backend №3.
