# Backend антискам-тренажёра

Go-сервис интерактивного тренажёра: каталог учебных сценариев и движок
прохождения с ветвлением.

Этот срез работает **полностью самостоятельно** — без PostgreSQL, Docker,
аутентификации, внешних API и кода других участников.

## Запуск

```bash
cd backend
go run ./cmd/api
```

Сервис поднимется на `:8080`. Проверка:

```bash
curl http://localhost:8080/healthz
```

Внешних зависимостей нет — только стандартная библиотека Go 1.25, поэтому
`go.sum` отсутствует и загрузка модулей при сборке не требуется.

### Настройки

Все переменные окружения необязательны.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HTTP_ADDR` | `:8080` | Адрес прослушивания |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `HTTP_READ_HEADER_TIMEOUT` | `5s` | Таймаут чтения заголовков |
| `HTTP_READ_TIMEOUT` | `15s` | Таймаут чтения запроса |
| `HTTP_WRITE_TIMEOUT` | `15s` | Таймаут записи ответа |
| `HTTP_IDLE_TIMEOUT` | `60s` | Таймаут простоя соединения |
| `HTTP_SHUTDOWN_TIMEOUT` | `10s` | Время на завершение активных запросов |
| `HTTP_MAX_REQUEST_BYTES` | `65536` | Предельный размер тела запроса |

## Проверки

```bash
cd backend
go fmt ./...
go vet ./...
go test ./...
go test -race ./...
golangci-lint run ./...
```

Конфигурация линтера — `.golangci.yaml` в корне репозитория.

`go test -race` на Windows требует установленного gcc (например, MinGW-w64).

## Endpoints

Источник правды — [`docs/openapi.yaml`](../docs/openapi.yaml).

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/healthz` | Проверка живости |
| `GET` | `/api/v1/scenarios` | Каталог, фильтр `?role=buyer\|seller` |
| `GET` | `/api/v1/scenarios/{scenarioId}` | Метаданные сценария |
| `POST` | `/api/v1/attempts` | Начать прохождение |
| `GET` | `/api/v1/attempts/{attemptId}` | Текущее состояние попытки |
| `POST` | `/api/v1/attempts/{attemptId}/choices` | Отправить выбор |

### Пример полного прохождения

```bash
BASE=http://localhost:8080/api/v1

# выбрать сценарий
curl -s "$BASE/scenarios?role=buyer"

# начать попытку
ATTEMPT=$(curl -s -X POST $BASE/attempts \
  -d '{"scenarioId":"buyer-fake-delivery"}' \
  | grep -o '"attemptId":"[^"]*"' | cut -d'"' -f4)

# отправить выбор
curl -s -X POST $BASE/attempts/$ATTEMPT/choices \
  -d '{"nodeId":"channel-decision","choiceId":"stay-on-platform","idempotencyKey":"step-1"}'

# перечитать состояние (например, после перезагрузки страницы)
curl -s $BASE/attempts/$ATTEMPT
```

## Архитектура

```text
httpapi          HTTP: маршруты, DTO, перевод ошибок в статусы
   ↓
service          сценарии использования (scenario.Service, attempt.Service)
   ↓
domain           правила сценария и прохождения, без HTTP и хранилищ
   ↑
storage/memory   адаптеры хранения, реализуют порты домена
```

```text
backend/
├── cmd/api/                 точка входа и graceful shutdown
├── internal/
│   ├── app/                 сборка зависимостей
│   ├── config/              настройки из окружения
│   ├── platform/            логгер, часы, генератор идентификаторов
│   ├── scenario/            модель сценария, проверка графа, каталог
│   ├── attempt/             прохождение: старт, переход, проекция
│   ├── storage/memory/      хранилища в памяти
│   └── httpapi/             HTTP-слой
└── scenarios/               файлы сценариев (встроены через go:embed)
```

Домен не импортирует `net/http`, драйверы БД и транспортные DTO. Порты
хранилищ объявлены рядом с их потребителями, а не в отдельном пакете
«интерфейсов».

## Ключевые решения

**Нулевые внешние зависимости.** Роутинг — `net/http.ServeMux` с паттернами
Go 1.22, логи — `log/slog`, идентификаторы — `crypto/rand`. Меньше рисков при
сборке, быстрее CI, нет чужого кода в цепочке поставки.

**Сервер владеет ходом сценария.** Клиент присылает только то, что нельзя
вычислить: какой узел он видел, что выбрал и ключ повтора. Следующий узел,
изменение результата и эффекты навыков берутся исключительно из файла
сценария. Подделать результат запросом невозможно.

**Содержимое сценария скрыто.** Каталог отдаёт метаданные, попытка — только
раскрытые узлы, вариант выбора — лишь идентификатор и подпись. Объяснение
последствия появляется после выбора. Правила и их проверка описаны в
[`docs/scenario-format.md`](../docs/scenario-format.md).

**Сценарии проверяются при старте.** Валидатор отвергает недостижимые узлы,
битые переходы, циклы и неполные последствия. Сломанный файл не даёт
приложению подняться — вместо ошибки у пользователя.

**Версия сценария закрепляется за попыткой.** Правка содержимого не изменит
уже идущее прохождение.

**Оптимистичная блокировка вместо мьютекса.** У попытки есть `version`;
хранилище принимает запись только при совпадении. Это ложится на
`UPDATE ... WHERE id = $1 AND version = $2` без изменений в сервисе.

**Идемпотентность на стороне сервера.** Повтор с тем же `idempotencyKey`
возвращает сохранённый снимок результата и не применяет эффекты повторно.
Тот же ключ с другими данными — `409`.

## Ограничения

Осознанные для этого среза:

- **Хранилище в памяти.** Перезапуск процесса теряет все попытки. Каталог
  сценариев read-only и восстанавливается из встроенных файлов.
- **Нет аутентификации.** `attemptId` — единственный секрет доступа к попытке,
  поэтому у него 128 бит энтропии. Публиковать его нельзя.
- **Нет ограничения частоты запросов.** Для публичного демо понадобится.
- **Итог сценария определяется последним решением**, ранние ошибки отражаются
  в результате. Ветвление по всей истории потребовало бы кратно больше узлов.
- **Нет пагинации каталога** — сценариев пока единицы.

## Точки интеграции

**Backend №2 — PostgreSQL и прогресс.** Заменяются только адаптеры в
`internal/storage/memory/`. Порты:

```go
// internal/scenario/repository.go
type Repository interface {
    List(ctx context.Context, filter Filter) ([]Scenario, error)
    Get(ctx context.Context, id ID) (Scenario, error)
}

// internal/attempt/repository.go
type Repository interface {
    Create(ctx context.Context, attempt Attempt) error
    Get(ctx context.Context, id ID) (Attempt, error)
    Update(ctx context.Context, attempt Attempt) (Attempt, error)
}
```

`Update` должен возвращать `ErrConcurrentUpdate`, если версия не совпала.
Для ключей повтора пригодится уникальный индекс `(attempt_id, idempotency_key)`.

Данные для подсчёта прогресса уже собираются: `Attempt.Decisions` хранит
критичность, метки риска и эффекты навыков каждого решения,
`AppliedSkillEffects` — их сумму. Сервисы и HTTP-слой менять не нужно.

**Backend №3 — контент, Docker, деплой.** Файлы в `backend/scenarios/`
заменяются целиком по описанию в `docs/scenario-format.md`. Приложение
собирается одной командой и не требует внешнего каталога — файлы встроены
в бинарник.

**Frontend.** Контракт зафиксирован в `docs/openapi.yaml` и уже работает.
Достаточно шести endpoint выше, чтобы собрать весь путь пользователя.
